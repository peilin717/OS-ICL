# OS ICL 当前三十六任务清单

本目录包含 36 个独立 ICL 任务族：Easy 12、Medium 12、Hard 12。任务通过 `/studio36` 创建，使用现有 OS 桌面与九个功能应用。夹具、局部示范和判定接口见 [TASK36_API.md](TASK36_API.md)。

## 采用的三档定义

| 档位 | inference 的必要结构 | Demo 的职责 | 数量 |
| --- | --- | --- | --- |
| Easy | 在多个新对象上反复多次执行 demo 的同一规则，逐对象保存与核验 | 清楚呈现规则、作用范围和必要边界 | 12 |
| Medium | 规则只是长程业务中的一个模块，其余环节承担资料关联、范围判定、成果制作、核验与交付 | 仅展示局部方法及必要自然导航 | 12 |
| Hard | 具备 Medium 的长程结构，并且现有 OS 内多个功能界面之间存在必要的内容或状态依赖 | 仍只展示局部方法，不以完整长程录像代替教学 | 12 |

Hard 的平台指系统内多个功能界面之间的必要内容或状态依赖。

为把边界设计得可检验，本清单让 Medium 在一个主要内置应用中完成，让 Hard 必须跨现有内置应用形成因果依赖。这是本清单的具体设计选择。单纯打开另一窗口、翻页、抄写一个已知字段或拍照式查看状态，不足以支撑 Hard；拿掉该界面提供的操作/结果后，后续业务必须无法合法完成。应用内普通文件选择器、设置页和属性对话框不单独累计平台数。

难度主要体现在 inference 执行，而非 demo 规则。Easy/Medium/Hard 均可学习简单的格式、映射、选择、排序或局部操作关系。次数、时长、点击数、窗口数和规则复杂度均不直接定义档位。

## 当前系统能力边界

只复用当前 static/desktop.js 和 workflows.py 已存在的九个应用及其操作。

| 现有界面 | 本清单复用的实际能力 | 不假设存在的能力 |
| --- | --- | --- |

| Notepad | Open 文件选择器、读取和编辑文本、Save、插入 form-feed 分页 | 自动合并器、自动报表生成器、另建业务表单 |

| Task Scheduler | 新建/编辑/重置/运行既有 kind 的作业，配置输入输出/依赖/trigger | 新作业类型、自动批量解题、任意外部脚本执行 |

| Terminal | 现有 offline-test、workspace-open、storage-audit、restore-check、pwd/clear/help | 真实 shell、任意程序、任意新验证命令 |

## 统一实例和评分契约

1. **持续环境**：一个 episode 对应同一个 OS 状态。应用切换不重置、不换实例、不显示解题进度。A/B/C 和不同试验条件使用独立上下文、写入状态和录制。
2. **公共初态一致**：同任务/seed 的 A/B/C 请求、文件内容、元数据、设置、任务、设备、过程状态和 UI 初态一致。只替换外部 demo 与可信评分所用局部规则。全部合法规则都能从同一公共初态执行；普通工具不按隐藏条件放行。
3. **一题一种教学关系**：公共请求给范围、修订、身份、接收方、时区、普通业务约束等；只有 A/B/C 表中一个局部方法由视频决定。联合配置仅当它本身是一个明确整体方法时使用，如 H05 的打印组合。
4. **反事实可辨识**：每题 witness 是生成器必须满足的约束，不只是说明。每个 demo 组与计分 query 的三个规则结果都应两两可区分；若阈值集合、排序、路径或格式结果重合，拒绝该 seed。参数对照例子只写在设计文档，不作为 query 答案。
5. **独立新材料**：demo/query 不共用对象、正文、答案和缓存。随机化资料关联、批准/撤回、版本竞争、依赖边、故障位置、范围与数值，而非只改文件名或行位置。公共稳定 ID 仅用于合法对应，不能编码隐藏条件。
6. **局部教学**：每个任务/条件使用一段 demo，覆盖清晰正例与必要反例。选择有竞争属性，阈值含等于边界，排序含并列，动态规则展示触发前后。健康/故障路径用于检验执行结构，不强行塞进静态格式 demo。
7. **任务保护范围**：源材料、历史版本、范围外对象默认保护。必须修改的目标文本、名称、父目录、设置、任务、进程/队列状态属于明确允许变更集。保留内容与保持身份/路径是不同要求：H07 B 明确允许保全对象改名，C 明确允许复制后清除原位置；不能套用“所有初始对象全部不变”的通用判据。
8. **真实结果评分**：逐对象核查保存内容、集合、顺序、来源、依赖、保护集和禁止副作用。严格成功为全部必要谓词的合取；最后一个正确不能覆盖前面错误；报告写 PASS 不代替实际结果。给出诊断完成度，但不以其替代严格成功。
9. **证据绑定与等价方案**：构建、测试、校样、快照、脱敏、干运行和收据须绑定实际消费版本。内容变更后相应证据须重做。允许等价操作顺序和无害导航；只检查规则或业务确实要求的局部顺序，不能强制参考鼠标路径。
10. **合理故障**：保留可恢复失败和日志，不能因历史上出现 Failed 就全题失败；只拒绝未解决故障、错误交付或禁止副作用。错误操作不应静默创造有效成果。不以等待、含糊资料和无意义点击增加难度。
11. **时间与数值**：使用确定性逻辑时间和可见冻结指标。公开时区、闭区间语义、计量单位、舍入、并列规则。A/B/C 阈值本身若属于学习关系，只在 demo 出现，不另写入 query 说明。
12. **复用虚拟语义**：现有 archive 是含实际虚拟资源内容的 provenance JSON，不声称真实 ZIP/TAR 容器；媒体预览是虚拟元数据，不声称验证真实编码。涉及内容比较时使用引擎 canonical-JSON 摘要约定，并与原始视频字节 SHA-256 区分。
13. **Agent 隔离**：模型只获外部目标 prompt、视频、截图和鼠标键盘。规则表、依赖图、评分谓词、状态 JSON、DOM、参考动作和语义 API 属于可信端。普通 UI 显示业务内容和保存状态，不显示下一步清单。
14. **英文运行环境**：本文中文 prompt 为审阅草稿，落地时转为同义英文并使用既有英文 UI；不把规则表、审计或判据一起注入。
15. **三种视频对照**：正确、错配和无视频分别重置运行。规则理解 QA 在独立上下文开展；区分“规则理解错误”和“关系理解正确但执行失败”。

36 题对应 108 个 A/B/C 条件，共 108 段演示。每次推理仅输入匹配条件的一段，query 使用独立实例。

## 逐题规格

箭头表示必要业务依赖，不是按钮教程。Medium/Hard 的方括号标识视频教授的局部模块。Easy 的主体是同一规则的反复应用。

### OS-E-01 批量规范文件名称

**档位理由**：Easy。多个新对象或对象组独立重复同一规则，没有额外独立长程业务链。

**现有界面**：File Explorer。现有 OS 内一个应用界面；不新增功能。

**Inference 请求草稿**：整理指定六份文档的名称，按视频学习的格式处理标题；保留内容、扩展名与范围外文件。

**Demo 呈现**：用两份不同词数的文件展示名称修改和扩展名保留；包含一个范围外文件。

| 条件 | 局部方法 |
| --- | --- |
| A | 词间空格改为连字符，连续空格折叠 |
| B | 词间空格改为下划线，连续空格折叠 |
| C | 每词首字母大写其余小写，词间一个空格 |

**Query 新实例**：六个新标题，含混合大小写和多空格；目标名称不碰撞。

**必要执行结构**：读目标身份→逐文件重复名称转换→核对全部名称。

**实际结果与保护谓词**：六份目标名称准确；内容、扩展名、父目录与身份不变；非目标不动。

**反事实见证**：季度 report.txt 在三条件得到不同名称；至少一份小写词用于区分 C。

**必须拒绝的错误解**：只改最后一份，或把扩展名也大写。

**现有操作依据与任务签名**：rename、properties；文件命名。

**实现状态**：复用现有界面操作；需新增任务夹具、局部示范和逐对象评测。

### OS-E-05 批量暂停高内存后台进程

**档位理由**：Easy。多个新对象或对象组独立重复同一规则，没有额外独立长程业务链。

**现有界面**：Task Manager。现有 OS 内一个应用界面；不新增功能。

**Inference 请求草稿**：对指定六个后台进程采用视频展示的内存条件暂停命中对象，未命中与范围外对象保持原状态。

**Demo 呈现**：展示低于、等于、高于阈值的进程及一个范围外对象；只使用当前界面已有 memory 数值。

| 条件 | 局部方法 |
| --- | --- |
| A | 内存达到 128 MB 时暂停 |
| B | 内存达到 256 MB 时暂停 |
| C | 内存达到 384 MB 时暂停 |

**Query 新实例**：冻结内存值含 127/128、255/256、383/384 MB；至少各有命中且初始 Running 的对象。

**必要执行结构**：读冻结内存→逐进程重复判定→暂停命中→核对状态。

**实际结果与保护谓词**：命中进程为 Paused；未命中初始状态保持；锁、名称及非目标进程不变。

### OS-H-11 存储清理与服务恢复

**档位理由**：Hard。规则仅是长程任务中的一个模块，且多个现有应用界面必须交换并消费内容/状态；不新增功能。

**Inference 请求草稿**：在可恢复和服务状态保持的前提下清理指定项目的可再生缓存，完成压缩与空间核算；维护报告的字节单位表示从视频学习。

**Demo 呈现**：只展示一个公开字节数转换成报告单位；基数为1024，定点 HALF_UP，原始字节数同时保存。

| --- | --- |

| C | 以 MiB 表示，保留六位小数 |

**Query 新实例**：storage 域缓存与伪装 .cache 用户笔记混合；所有者初始状态混合；备份未完成，存储统计含生成报告与压缩对象。

**必要执行结构**：Files 属性区分可再生对象→Settings 启工具与保护备份参数→Scheduler backup/verify-backup→Task Manager 暂停实际所有者→Files 仅删可再生缓存→Scheduler compact/compare→恢复各所有者→Terminal storage-audit→Notepad [单位转换]并保存报告。

**必要跨界面依赖**：

- Files regenerable/owners→Task Manager 暂停范围。
- Scheduler 校验备份→Files 缓存删除被允许。
- Files 删除与进程恢复→Terminal audit→Notepad 数值报告。

**现有操作依据与任务签名**：properties/backup/process/delete/compact/storage-audit/write；精确清理与状态/空间守恒。

## 独立性审查与合并条件

同一种局部方法可以出现在多个档位，符合用户“难度在执行”的要求；但每个计数任务还必须拥有不同的业务目标、必要依赖和实际结果。不能把同题复制一份，仅加窗口或换名称填满配额。

| 易混组合 | 决定任务身份的差异 | 退回条件 |
| --- | --- | --- |
| E01 / E10 / E12 | 文件名；限定正文作用域；单个分页边界 | 都退化为改同一普通字符串字段 |
| E02 / M01 | 独立文件归档；批准修订选择、资源依赖闭包及保护冲突后的交接集合 | M01 只是把 E02 重复更多次 |
| E03 / M01 | 各组独立选一个版本；一个交付目标下跨组依赖集合必须同时成立 | 交接题没有任何跨组约束 |
| E05 / H08 / H11 | 独立内存阈值暂停；构建测试恢复；受备份保护的缓存维护 | Hard 只暂停进程并写报告 |
| E06 / H09 | 既有副本逐份字段转换；从原始事故日志定位窗口、跨通道关联并生成受校验的证据包 | H09 只多开 Settings |
| E08 / M06 / H09 | 多锚点窗口重复导出；已导出材料的处置时间线证据；原始日志到共享脱敏档案 | 三题都只导出日志 |
| E09 / M08 | 既有任务单字段反复配置；受影响依赖子图的重建和内容继承 | M08 没有依赖/输入影响范围 |
| M02 / H02 / H08 | 版本说明/配置一致；工具与签名发布；锁与独立构建/测试双阶段恢复 | 三题只修同一版本字符串或 tools 开关 |
| M04 / H07 | 已复制副本的成套引用；实际数据迁移、目标编辑保全与应用启动 | 迁移题不执行 migrate/workspace-open |
| M05 / H05 / H12 | 可编辑母稿及实际页码；首次校样/提交；已有队列撤回、重置并唯一重发 | H12 没有旧队列和生产者重置保护 |
| H01 / H08 | 指定历史配置回退并由新作业验证；当前构建故障修复及锁状态恢复 | 配置回退题被改为再修一次构建 |
| M09 / H03 | 为当前已就绪输入新建并验证回滚点；历史快照完整性选择、下载与任务重新激活 | 灾后题只再跑一次 backup/restore |
| M10 / M11 | 申请和佐证决定授权字段变更；库存流入流出与批次守恒 | 两题只保留同一种批量文本变换 |
| M12 / M07 | 基线上的双源字段合并；文件级新增/更新/退出同步 | 字段合并被整文件覆盖替代 |
| H04 / H06 | 素材/字幕/预览身份与尺寸；离线缓存资源与绝对引用 | 两题都是下载后直接打包 |
| H10 / M08 | 共享盘 recipient/权限/载荷干运行与未派发计划；纯 Scheduler 依赖子图重建 | H10 没有真正的 share 和权限门槛 |
