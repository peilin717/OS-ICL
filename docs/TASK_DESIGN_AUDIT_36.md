# OS ICL 三十六题设计自审记录

日期：2026-10-15。审查对象为 [新版清单](TASK_CATALOGUE_36.md) 及 [结构化规格](TASK_CATALOGUE_36.json)。

这是同一设计者连续五轮的文本和源码能力对照自审，不是独立审稿、运行测试或模型评测。每轮记录质疑、实际修改和剩余验证。最终清单是候选设计，不能因完成自审而宣称 benchmark 已实现。

## 第一轮 难度定义和保留系统范围

**质疑**：把“跨平台”解释成新建外部业务系统，是否偏离用户本意？中、高是否实际只有窗口数差异？

**发现与修改**：

- 用户明确 Hard 指现有系统内多个界面互动。删除 ServiceDesk、ReleaseHub、AssetHub、TeamHub 以及浏览器、上传导入、外部授权/资产/部署的整套方案。
- 所有 Hard 改用当前九个应用。逐题列出界面间实际消费关系，不能以打开多个窗口计数。
- Medium 采用单一主要应用长程业务，Hard 采用跨内置应用的必要协同，作为本清单清晰的设计边界。
- 配额保持 12/12/12，A/B/C 和 seed 不计为独立题。

**剩余验证**：落地后去掉每个 Hard 上游界面的状态变化，确认后续不能合法完成；当前只是把这些必要条件写清楚。

## 第二轮 当前功能可执行性

**质疑**：是否为了凑题暗中要求尚未实现的控件、解析器或业务能力？

对照读取 workflows.py 的 mutate/job_error/run-job，domain_checks.py 的 configure/probe，以及 static/desktop.js 的九个应用、表单、菜单和 Terminal 命令。

**发现与修改**：

| 前稿问题 | 最终修改 |
| --- | --- |
| 进程优先级编辑和 CPU 规则 | E05 改为现有 memory 与 Running/Paused |
| 应用级通知投递策略 | 撤去，E06 改为 Notepad 日志副本字段转换 |
| 设备刷新、移除配对、重配 | E07 只使用已实现连接/断开 |
| 打印队列重排 | E11 改为已有 Pause/Resume |
| 文件角色 ACL/真实身份验证 | 撤去；E12 改用已有插入分页 |
| 批准日期属性选择 | E03 只用已有 approved/revision/bytes |
| offline URI、变量路径解析 | M04/H06 只用现有支持的绝对路径 |
| 自动工具版本安装与自动合并器 | 不作为考点；M12 以普通文本编辑完成字段合并 |

**剩余验证**：任务初始化和逐题评分仍需实现；复用控件不等于新任务已能运行。不为本清单新增系统功能。

## 第三轮 独立任务族与重复包装

**质疑**：是不是同一个复制/重命名/写索引/跑六个作业的模板换题名？是否将 Medium 仅加一个故障就另算 Hard？

**发现与修改**：

- M09 从素材预览流水线改为创建回滚点并恢复比较；H04 保留相机补录、sidecar 和预览的实际媒体业务。
- M10 从共享盘分发编排改为人员资料申请/佐证核对，避免与 H10 仅差连接故障。
- M11 从 JSON 配置修复改为库存批次对账，避免与 M04 仅差路径修订场景。
- H01 从锁定数据集活动切换改为历史处理环境配置回退，避免与 M07 的同步工作主要依赖仅差一次 Pause。
- H12 判已提交旧版的取消、生产者重置和唯一新版重发；H05 判首次校样和提交。区分来自已有 print-control/update-job 保护关系，而非“高风险”标签。
- M02 的产物是版本说明成套文档；H02 的目标是工具修复后的签名发布，M02 不假称完成后者。
- M09 是对当前输入新建可恢复点；H03 是从历史快照重新激活项目及任务，不可互相替代。

**剩余验证**：最终清单列出逐组退回条件。必须在实际夹具与结果图中保留上述差异；标题或签名字符串唯一不能证明独立性。

## 第四轮 视频学习必要性与反事实

**质疑**：模型是否不看视频也能从默认值、原始请求或固定答案完成？三规则在某些 seed 是否其实结果相同？

**发现与修改**：

- 每题加入具体 witness，要求 A/B/C 结果两两可分；阈值含边界与不同命中集合，排序有竞争和并列，格式有足够非平凡输入。
- H05 的旧版 print_request/cover 可能明写固定纸型与双面。新夹具必须移除该答案，三个打印组合都保留可行设备。
- M08 不再沿用现有任务名作为答案，新建受影响替代链才应用示范名称方式。
- M12 使用两个时间先后相反的冲突字段，避免 C 总是等于整份 A 或 B。
- H06 删除新 URI 解析形式，三条件只改变已支持的文件命名及相应绝对引用。
- 同 seed 的公共初态和工具合法性必须一致；不能按隐藏规则只允许一种打印组合或目录。
- 不沿用旧版一次改变多组全局 convention 的规则包。公共范围、时区、收件方等不从视频隐藏学习。
- 三种视频条件需独立 reset。正确/错配/无视频控制与规则理解 QA 的上下文隔离写入契约。

**剩余验证**：当前 witness 是设计样例与生成约束，没有运行生成器验证所有 seed。需要后续编程检查及视频可辨识审核，不能预先声称无视频一定失败。

## 第五轮 真实结果、来源与评分捷径

**质疑**：是否只靠显示 PASS、正确文件名、最后一个对象或旧证据就能通过？是否复用了不适合新规则的旧评分约束？

**发现与修改**：

- 所有题加入明确的错误解和逐对象结果/保护谓词；报告不是实际任务完成的替代品。
- H08 摘要改为现有测试文件实际字段 build_artifact/passed/assertions；project/revision 从断言读取，不虚构顶层字段。验证真实测试，不允许篡改源规格让错误断言通过。
- H09 明确沿用原通道工作副本 source 身份承载导出内容，使当前 redact 消费路径成立，不假设任意新文件自动成为 source-0/source-1。
- H07 三种保全明确允许的身份/名称/位置变更，防止旧版“所有初始对象不变”误杀正确方案。
- H11 区分释放缓存字节与总 Used 变化，考虑新增备份、报告和压缩对象；原本 Paused 的进程不能统一 Resume。
- H12 必须取消旧队列后再重置生产任务，最终仅一份有效新稿；只 Pause 旧稿不算撤回。
- 保留恢复失败记录，不套用“出现历史 Failed 就全部失败”的旧通用条件。
- 沿用虚拟资源和 canonical-JSON 摘要的实际语义，不把元数据 JSON 宣称为真实 ZIP、媒体编解码或宿主执行。

**剩余验证**：这些是评分实现需求；尚未以已实现 evaluator 执行变异攻击。后续必须对错内容、错身份、旧证据、漏对象及禁止副作用逐项运行拒绝测试。

## 自动结构检查的实际范围

交付时的脚本仅检查 36 条、12/12/12、ID 唯一、A/B/C 非空且不同、必填字段、见证/负例、Medium/Hard 局部模块标识、单主要界面与 Hard 跨界面依赖声明，以及 Markdown 与 JSON 的题目对应。

这不能自动证明任务独立、依赖真实、三结果在生成器中两两可分、视频可辨识或系统功能可达。运行证据均留待实现阶段。结构报告见 [DESIGN_CHECKS_36.json](DESIGN_CHECKS_36.json)。

## 最终处置

- 保留 36 个设计任务族，三档各 12。
- 撤销新增外部平台、新系统功能和“内置界面不算跨平台”的旧解释。
- 当前自审结论为“可进入逐题夹具与评分实现”，不是“已通过 benchmark 验收”。
- 现有系统 UI、引擎和录像保持；本次仅保存设计文件并修订相冲突的任务设计指令。
